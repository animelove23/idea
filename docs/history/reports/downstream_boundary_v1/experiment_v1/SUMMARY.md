# Alignment v1.1 实测结论

测试完成。部分已知配对问题得到改善，但本轮没有证明整体稳定性提高。

同一批 8 条真实 caption（4 对）使用既有 8-shot 独立运行 3 轮，发出 48 次 DeepSeek 请求；47 次取得返回，1 次在 120 秒超时。全程关闭思考。原始 Decomposer、caption、facts、示例和本轮冻结的规则均未改动，也未补跑超时来替换失败记录。

每轮固定有 78 条原始主线事实，两侧均计入；3 轮共 234 条事实分配记录。跨轮采用 3 个两两组合，每组比较同一批 78 条事实，分母也为 234，但表示的是重复比较次数。严格一致要求状态和对侧事实的文本、类型、语气、极性签名相同；ID 不参与。技术失败不能获得一致性分数。

校验拒绝率的下降部分直接来自校验器改动，不能当作语义质量提升的证据。这是同一开发集上的历史前后对比，同时改变了提示词和校验器，不是并行随机对照或单一因素消融。没有完整人工对齐 gold，因此不报告 accuracy、precision、recall 或 F1；高一致性也可能来自重复犯同一个错误。

## 尚未解决的问题

1. **花瓶的组合关系波动**：第 1、3 轮把“装有干花”与“装有花和草”标为 modified，但参与对象列表不同，被校验拒绝；第 2 轮标为 partial_overlap 并通过。这里需要明确集合增减与局部保留的边界，不能只凭是否通过程序判对错。
2. **长颈鹿存在与数量重复承载**：第 1、3 轮模型把 entity 与 counting attribute 合并为一个 retained 组，因类型不同被拒绝。既有 entity fact 已含“two”，可能诱发这个分组；本轮保留原始数据，不在测试中途更改。
3. **服务超时**：第 2 轮长颈鹿事实对应超时，影响 18 条原始主线事实。单独计为 API 失败，不混同语义错误。
4. **复合事实的局部丢失**：“field filled with tall grass”在两个成功返回的轮次均被标 removed，但 Steer 仍提 grassy field；这仍需审核是否应使用局部重叠，而不能仅凭结果重复就认为正确。

每轮只有鞋子样本产生 1 条关联引用，三轮成员、状态和原因一致。全样本关联引用集合比较为 12/12 相同，但其他三个样本均为空，且其中一次整体超时，这个数字不代表关联引用召回率。旧版没有这一机制，其空集合一致性不宜作质量对照。

## 记录与完整性

完整性检查通过：每条事实恰好一个主对应，关联引用不重复计数；Coverage 仅追加；原始事实不变；冻结代码、配置与示例哈希一致；所有视觉验证标签保持 pending。三轮分别保留 87 条待验证事实，共 261 条。

已返回的 47 次请求合计记录 360,554 tokens（输入 340,090，输出 20,464）。超时请求没有 usage 返回，故不是完整计费总量。
