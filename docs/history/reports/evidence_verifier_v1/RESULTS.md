# 错误定位、结构化证据改进与定向复核

**本轮有净改善，但还不能交付实体准确率90%以上的视觉评估器。** 以原60条候选参考计，整体47/60→51/60，实体33/41→34/41，属性14/19→17/19。原参考未改、困难样本未删。

完成120次原版/证据版对照和8次自动候选框复核，共128次官方DeepSeek请求；后续编译器修复没有再次调用模型。新增三个代码组件（证据接口、标签编译器、定向复核），主框架生产默认未更换。109项离线测试全部通过。

## 1. 查实的问题

### 证据到标签没有可检查的决策边界

旧模型会一边描述“装饰人偶”“指定区域没有车辆”，一边给uncertain。旧`validate_label`只检查label和reason的类型，不验证为什么U，也不能区分目标不存在与目标看不清。

本轮把“找到匹配实例／明确替代物／未找到／候选未决”和“搜索区域可检查／受限”分开，由代码生成最终标签。373677人偶、279634入口的车、462687披萨三条从U恢复H，6条参考H实体全部检出。这支持了“判定边界有缺口”这一解释，但模型现在也会把模糊区域误称可检查，仍会制造错误H。

### 文本主体语境不等于视觉实例定位

381925小狗的证据版返回具体候选框但仍为U。用这个自动框生成局部视图后变S；同样再请求一次原图仍为U。这给出了定向局部视图对该案例有用的对照证据。

565761领带则没有返回任何候选框，理由仍围绕“背对镜头或远处的坐着的人”。画面中的主体选择/可见性判断未完成；不能把source_mentions和source_window存在误当成已经正确定位。

519838远车给出了框，但复核仍无法确认。其ROI返回框[295,85,400,113]按声明的0..1000原图坐标投影，落在左上树叶而非右上车辆位置；数值接近原图像素坐标，可能存在坐标单位混淆。这里只能确认返回框不可信，不能断言模型内部原因。框保留`bbox_verified=False`，不继续用它自动裁图或绑定属性。

### 区域可见性、类别判断仍会出错

352377：前景梨形水果仍被判断为苹果；橙子从S回退U；模糊背景香蕉从U变H。195269远车也由U变H。这些错误发生在candidate_status/region_status等视觉观察字段上，代码可以保持标签与字段一致，却不能证明字段本身正确。

因此不能再通过“更保守”“更果断”或统一增加局部图片解决全部问题。剩下的核心是实例定位、搜索范围及区域可判定性。

### 参考与命题范围存在争议

69946岸边车辆可见，但旧参考仍是U；519838远处车辆的可辨阈值也有争议。旧40图曾允许“对象类别不符但同一对象的属性独立支持”，当前M5要求完整命题支持。两套口径必须审核统一，不能在调参过程中把参考改成模型答案。上述旧参考本轮全部保持不变。

## 2. 实际改动

1. **单次结构化视觉观察。** 输出目标候选状态、观察到的类别、搜索范围、可见特征、证据限制、候选框及属性状态，不让模型直接给最终三分类标签。模型、原图、原命题、查询语境、6个示例的图片和问题不变；示例输出与system prompt同步换成证据合同。这是模块接口干预，不是单句提示消融。
2. **确定性标签编译。** 可检查区域中的明确替代物/缺席→H；已确认主体及完整命题→S；主体或证据未决→U。主体未确认时，属性字段单独支持不能把完整命题升级为S。
3. **修正过严的程序规则。** 初版强制所有属性请求都填写属性判断，导致“umbrella实际是茅草棚”的合理not_applicable被当技术失败。`compiler.py`只在主体未建立时允许属性N/A，保留原始证据；用原响应重编译，483723_v1由技术失败恢复H。没有放宽匹配主体的属性校验，也没有改原始调用结果。
4. **有限的自动定向复核。** 只对模型未决、有框、面积≤15%、限制是视觉问题的实体，按同一25%边距规则生成一个原像素局部图；同时保留完整原图。四条全部按同一规则处理，不读取参考标签，也不挑最好的预测。

六个示例仍覆盖实体/属性三类标签原含义，没有把本轮测试图加入few-shot。新模块不增加额外裁判或投票；正常每条一次调用，触发定向复核的条目至多多一次。按本批触发率，候选路径本身为60+4次；本轮128次包括60次原版对照和额外4次原图重复对照。

四条候选为381925小狗、381925遥控器、519838远车、54264远车。小狗是唯一新增正确项；其余三条未提升。原图重复也未改善总体正确数，不能将小狗的提升仅解释为“又问了一次”。这只是单轮、四条开发跟进，不是稳定因果估计。

相对原版，最终实体修复4条、回退3条，净增1条；属性修复3条，净增3条。属性改进包括large bird/airplane不再直接依类别常识判S，以及483723衣物颜色从U恢复S；房间large仍未解决，屋顶red仍与参考U不符。

**风险没有消失。** 实体错误确定判断从2条增至4条，虽然整体错误确定判断仍为5条。主体H召回从3/6升到6/6，同时对原U作出了两个错误H。实体至少37/41及不增加错误确定判断的门槛未通过，不能只凭整体提升替换主框架。

## 4. 可用与不可用范围

- 可用：保留具体视觉观察、搜索范围、框、限制原因和代码决策路径；定位标签不一致与错误观察发生在哪一层；继续固定输入做模块试验。
- 尚不可用：把模型框当视觉grounding真值，宣称同一主体已正确绑定，宣布跨调用稳定性或新图泛化达到90%，把当前成绩直接用于最终语义关系结论。
- 单条证据内的主体/属性约束由程序保证；多个独立请求仍可能对同一主体给出不同观察，需要framework_v2的跨命题分母账本继续审核。
- 原图像、语义参考及旧运行结果均保留；compiler修复、候选选择和两组复核输出分开记录。ROI跟进在观察部分开发输出后设计，不能称盲测或预先独立确认。

下一项应针对“实例框与区域可判定性”建立独立复核，不再扩大无效切图：先冻结每条命题的搜索范围与类别口径，再评估定位器的目标覆盖/误定位率；同时用独立人工裁决解决少量参考争议。不能靠坐标数值合法、共同错答或删除U样本来过90%门槛。
